# VOICE core: handoff for a second app

Written 2026-10-30 from VOICE Beta 3.3 (repo `rwawrzonkowski-dotcom/AAC-App`, folder `beta/`).
Purpose: start a new app from the reusable parts of VOICE without copying the AAC-specific parts or re-learning the hard lessons.
Give this file to Claude at the start of the new project, together with `docs/VOICE-STATUS.md`.

## 1. What VOICE is built from

- Plain HTML, CSS and JavaScript modules: no framework, no build step, no runtime network, no CDN. All paths are relative.
- About 12,400 lines: 52 JS modules, one `styles.css` (about 1,000 lines) and one `index.html`.
- Assets: about 11 MB of open symbols (1,386 SVGs), 0.5 MB of JSON data, 1.5 MB TensorFlow.js and an 18 MB COCO-SSD model. The model loads only when needed.
- Hosting: GitHub Pages. The stable copy is the repo root and the test copy is `beta/`. Each copy has its own storage prefix and cache prefix.
- Offline: a service worker (`sw.js`) caches every app file. Its file list is generated by `tools/update-cache-list.py`. Large models go in a separate cache that is filled lazily and never deleted.
- Privacy: everything is stored on the device (IndexedDB plus localStorage). There are no accounts, analytics, ads or tracking. Files leave the device only when an adult taps Backup or Export.

## 3. Rules that went with VOICE (decide which carry over)

1. Layout never moves. VOICE: a word never changes place. A second app may want the same "nothing jumps" rule for any child-facing screen.
2. Adults deliver reinforcement. The app does not play rewards.
3. Teaching is opt-in. Fading is automatic; mastery is only ever suggested to the adult.
4. Child photos and data stay on the device. No accounts, ads or tracking.
5. Use open, credited sources only (see `CREDITS.md`). Never use PCS or LAMP material.
6. Adult features sit behind a hold plus an optional passcode, and are styled to look different from the child's screen.
7. Every change goes to beta first and is promoted only after testing. Restore points are branches (`stable-1.0`, `stable-1.1`, `stable-2.0`) because tag pushes are blocked.

## 4. Hard-won lessons (do not relearn these)

1. **iPad camera:** Safari opens the camera from a file input only on a real tap that lands on the input itself. Opening it from `input.click()` after a long press is silently blocked. Fix: arm the button, lay the input over it after the finger lifts, and let the next tap open it.
2. **Storage eviction (fix before the pilot):** iPad Safari may erase a website's stored data after about 7 days without use, unless the app was added to the Home Screen. VOICE does not yet call `navigator.storage.persist()` or check that it is running from the Home Screen. The new app should do both from day one.
3. **Service worker updates:** install with `cache: "reload"`. Each copy deletes only caches with its own prefix. Every version bump currently re-downloads every file (about 13 MB). Better: put content hashes in the file list and copy unchanged files from the old cache.
4. **Board geometry:** test cell boxes before and after every layout change with Playwright (headless Chromium, 1180×820 and 1024×768, 45 and 84 grids). The test serves the parent folder with an `AAC-App` symlink.
5. **Safe areas:** on iPhone, equal side margins keep buttons clear of the notch, and centering keeps the board still when the phone rotates.
6. **Speech:** iPad voices differ by device. Show only installed voices, offer "Test the volume", and remember that the silent switch and Bluetooth routing affect output.
7. **CSV:** guard against formulas (text starting with `= + - @`, tab or return gets an apostrophe in front).
8. **Testing hygiene:** run Python with `-u`; never `pkill -f` a pattern that matches your own shell; use a persistent browser context to test upgrades.
9. **Git:** commit as `Claude <noreply@anthropic.com>`. Pages builds take 1 to 2 minutes, and testers must fully close and reopen the app.

## 5. Recommended first steps for the second app

1. Make a new repo. Copy the "take as is" files plus `tools/`, `sw.js`, `CREDITS.md` and a minimal `index.html`/`styles.css`.
2. Set a new storage prefix, DB name and cache prefix in `channel.js` and `sw.js` so the two apps never share data on one device.
3. Add `navigator.storage.persist()` plus a "please add to Home Screen" check on first run.
4. Copy the teaching engine (`teaching.js` and `teachdata.js` first, since they are pure and testable). Rename the target type and keep the fading and mastery rules.
5. Copy `reportdata.js` and `reportcharts.js`, then build screens on top of them.
6. Decide early whether the two apps should share learners (the same child on one iPad). If so, agree on one export format between them now.
